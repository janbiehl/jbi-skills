# Article types

Skeleton per article type, and length orientation per medium. A skeleton is a
sensible default, not a contract: adapt it to the topic, and take the medium's
own requirements over it whenever they exist.

## Length orientation

Use these only to propose a concrete number when the user has none. The
editor's or publisher's specification always wins, and platform limits change —
check the current one when the text is close to it.

| Medium | Usual unit | Orientation |
| :--- | :--- | :--- |
| LinkedIn or similar post | characters | 150–300 words; stay well under the platform's character limit |
| Company or personal blog | words | 800–2,000 words |
| Tutorial on a blog | words | 1,000–3,000 words plus code |
| Trade magazine (Fachzeitschrift) | characters incl. spaces | per editor's spec; one printed page holds very roughly 3,500–5,000 characters depending on layout and images |
| Conference paper | pages | per call for papers and its template |
| Internal wiki page | words | as short as the reader's task allows; 300–1,200 words |

Converting between units: German prose runs at roughly 6.5–7 characters
including spaces per word, English at roughly 6. Use this to translate a
character limit into a word budget for the Gliederung, then measure in the
medium's own unit.

## Fach- oder Grundlagenartikel

Explains a concept, technique, or architecture so the reader can judge or use it.

| Section | Share | Content |
| :--- | ---: | :--- |
| Einstieg | 10–15 % | The concrete problem the reader has; the Kernaussage |
| Einordnung | 10–15 % | Where this sits, what it is not, prerequisites |
| Kern (2–4 sections) | 45–55 % | One idea per section, each with an example |
| Praxis | 15–20 % | A worked case or a listing that shows it applied |
| Grenzen | 5–10 % | When not to use it, known trade-offs |
| Fazit | 5–10 % | The Kernaussage paid off, a next step for the reader |

## Tutorial

Takes the reader from a defined start to a working result.

| Section | Share | Content |
| :--- | ---: | :--- |
| Ziel | 5–10 % | What the reader will have at the end — show the result first |
| Voraussetzungen | 5–10 % | Versions, tools, prior knowledge, as a list |
| Schritte | 60–70 % | Numbered; every step ends with something the reader can check |
| Fehlerbehebung | 5–10 % | The two or three errors readers actually hit |
| Weiterführend | 5 % | Where to go from here |

Every version number in a tutorial comes from the user or the material — a
tutorial that does not run on the stated versions is worse than none.

## Praxis- oder Erfahrungsbericht

Reports what a team did, what happened, and what others can take from it.

| Section | Share | Content |
| :--- | ---: | :--- |
| Ausgangslage | 10–15 % | Context, constraints, why it mattered |
| Ziel | 5–10 % | What success was supposed to look like |
| Vorgehen | 30–35 % | Decisions and the reasons for them, including dead ends |
| Ergebnisse | 20–25 % | Numbers where there are numbers — only real ones |
| Lessons Learned | 15–20 % | What they would do differently; what transfers |
| Fazit | 5 % | The one recommendation |

## Vergleich

Compares options so the reader can choose for their own situation.

| Section | Share | Content |
| :--- | ---: | :--- |
| Einstieg | 10 % | The decision the reader faces |
| Kriterien | 10–15 % | Stated before the candidates, with why each matters |
| Kandidaten | 30–40 % | Each option against the same criteria |
| Gegenüberstellung | 15–20 % | A table — criteria × candidates |
| Empfehlung je Szenario | 15–20 % | "For X, choose A, because…" — not one winner for everyone |
| Fazit | 5 % | |

State how the comparison was made (versions, test setup, date of evaluation) —
a comparison without its method is an opinion.

## Meinungsbeitrag

Argues one position.

| Section | Share | Content |
| :--- | ---: | :--- |
| These | 10–15 % | The position, stated plainly in the first paragraph |
| Begründung | 45–55 % | Two or three arguments, each with evidence or an example |
| Gegenposition | 15–20 % | The strongest counter-argument, stated fairly, then answered |
| Schluss | 10–15 % | What should change, and who should do it |

## Produkt- oder Projektvorstellung

Introduces a product, tool, or project to people who might use it.

| Section | Share | Content |
| :--- | ---: | :--- |
| Problem | 15 % | The reader's problem, not the product |
| Lösung | 15–20 % | What it does, in one paragraph |
| Funktionsweise | 30–35 % | How it works, with a listing or a figure |
| Einsatz | 15–20 % | A concrete use case |
| Stand und Verfügbarkeit | 10 % | Status, licence, where to get it — from the user only |
| Ausblick | 5 % | |

Watch the tone: a technical audience stops reading at the first superlative.
Claims of being faster, cheaper, or better need a number and its source.

## Social-Media-Beitrag

One point, read on a phone.

- The first one or two lines carry the hook — most readers see only those
  before the text is folded.
- Short paragraphs, one or two sentences each, separated by blank lines.
- One point per post. A second point is a second post.
- End with a question or a clear next step, not a summary.
- Hashtags only if the user wants them; at most three, at the end.
